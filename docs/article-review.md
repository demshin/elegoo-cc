# Сверка статьи с источниками

Сборка проверяет структуру и ссылки. Сверка содержания проверяет каждое существенное техническое утверждение: кому применим совет, что именно помогло и какими независимыми случаями это подтверждается. Испытания на реальном принтере учитываются отдельно.

## Заключение

Проверяющий читает статью целиком либо весь изменённый фрагмент вместе с его контекстом. Для каждого утверждения фиксирует источник, дату обращения, подтверждённый результат и ограничения. Советы без результата и продолжения одной истории не увеличивают число независимых успешных случаев. Отдельно проверяются противоречия, неудачные попытки, предупреждения, численные параметры и различия моделей.

Публичные основания хранятся в обезличенных реестрах docs/evidence*.md и открытой документации. Исходная переписка остаётся закрытой. Владелец может сверять архивные указатели локально; внешние участники прикладывают открытые источники и собственные обезличенные отчёты в Issues и PR.

Итог проверки:

| Значение status | Что означает |
| --- | --- |
| supported | Все существенные утверждения проверенной редакции поддержаны просмотренными источниками с указанными в статье ограничениями. |
| partial | Подтверждена часть утверждений; в заключении перечислены пробелы. |
| contradicted | Найдено существенное противоречие источникам. |
| insufficient | Данных недостаточно для заключения. |

Поиск совпадений, наличие ссылки и оценка ИИ сами по себе не подтверждают решение. Для допуска новой статьи сохраняются требования повторяемости и успешного исхода. Решение о принятии PR остаётся за владельцем с учётом обсуждения сообщества.

## Публичный реестр сверок

[site/article-reviews.json](../site/article-reviews.json) содержит только краткие обезличенные заключения. Ключ в reviews — путь статьи, например faq/printing/empty-start-skirt.md. Поля записи:

- content_sha256 — SHA-256 точного UTF-8 текста проверенного файла.
- reviewed_on — дата фактической сверки в формате YYYY-MM-DD. Дату редактирования статьи сюда не переносят автоматически.
- status — одно из значений таблицы выше.
- summary — краткое основание итога и важные ограничения; без цитат переписки, имён и контактов.
- evidence — непустой список ссылок на открытые документы или публичные реестры проекта. Внутренние пути задаются от корня репозитория, с якорем при необходимости. Пути data/ в это поле не добавляются.

Сначала выполняется сверка, затем записывается её итог. Успешная сборка или прежняя дата «Сверка» внутри статьи не создают запись в реестре. Если текст изменён после проверки, сайт сообщает об устаревшем заключении по несовпадению SHA-256. Если записи нет, сайт показывает основания и отсутствие отдельного заключения для текущей редакции.

Если изменились только язык и расположение материала, отдельный проверяющий сопоставляет исходную и новую статьи целиком: утверждения, условия, предупреждения, числа, ссылки и степень уверенности. После такой проверки можно добавить editorial_review с полями from_content_sha256 (хеш ранее сверенной статьи), content_sha256 (хеш новой редакции) и reviewed_on (дата сравнения). Исходные content_sha256 и reviewed_on фактической сверки сохраняются. Сайт показывает обе даты в раскрываемом блоке «Источники и проверка» внизу статьи. Это проверка сохранности смысла, без нового заявления о прочтении архива или испытании принтера. Наличие ссылки или успешная сборка такую запись не создают. Новая техническая рекомендация требует обычной сверки, а не только редакторского сравнения.

Обе ссылки по хешам должны совпасть: from_content_sha256 с исходной записью, а content_sha256 с текущей статьёй. Любое дальнейшее изменение текста снова делает заключение устаревшим. При повторной фактологической сверке можно обновить основную запись и убрать editorial_review; цепочки непроверенных правок автоматически не продолжаются.

Локальное подробное заключение хранится в data/.work/article-reviews/ и не публикуется. Локальный скилл владельца faq-verify помогает пройти эту процедуру; сам скилл и архив не входят в Git и CI. Для публикации краткого итога нужно проверить обезличивание и выполнить обычные проверки проекта.
