# Объём и метод пробного разбора

Дата: **01.11.2026**. Результат: три статьи для проверки структуры и глубины. Это не полный FAQ по всем моделям и не исчерпывающий список проблем выгрузки.

Это исторический отчёт первого этапа. После согласования формата выполнено [тематическое расширение](topic-map.md); его текущие статьи перечислены в [оглавлении](../README.md).

## Что обработано

- Одна HTML-выгрузка Telegram: 16 страниц `messages*.html`, суммарно 51 777 097 байт HTML.
- Период обычных сообщений: 21.08.2025–31.10.2026, по датам в экспорте.
- Индексировано **78 458 обычных сообщений**, из них **71 779** с непустым текстом.
- Служебные сообщения не входят в индекс. Из ссылок-ответов 43 287 ведут на присутствующие в HTML служебные записи, включая корни тем; ещё 579 ведут на отсутствующие в выгрузке записи. Отсутствующий контекст не восстанавливается предположениями.
- Все 16 страниц прошли машинный разбор и поиск по словарям тем. Человекоподобное чтение всего текста не выполнялось: вручную разобраны выбранные эпизоды и их контекст из [реестра оснований](evidence.md).
- Просмотрены два фото первого слоя: у сообщений 15025 и 55697. Остальные фото, видео, голосовые и вложенные файлы по всему архиву не анализировались.

Количество сообщений сверено с количеством HTML-блоков обычных сообщений; повторяющихся ID в индексе нет. Это проверяет полноту извлечения блоков, но не полноту смыслового анализа или распознавание содержимого вложений.

## Как отбирались темы

1. Искались сочетания симптомов и сообщений о результате: первый слой, очистка, подача, сеть, веб-интерфейс, выравнивание и другие диагностические темы.
2. Для кандидатов читались ответы и контекст. Однотипные сообщения одного автора объединялись.
3. Для каждой включённой проблемы найдены независимые эпизоды повторения и явный успешный исход. В реестре отдельно отмечено, где успех только один, где действий несколько и где эффект временный.
4. Сведения сопоставлены с официальной ELEGOO Wiki. Случаи CC1 не объявляются подтверждёнными на CC2 или CANVAS только из-за похожего симптома.
5. Подготовлены статьи с разделами для двух аудиторий, проверкой результата и границами применимости.

Поиск по словам пропускает неявно описанные случаи. Выбор трёх тем не означает, что они самые частые. Числа в реестре дают нижнюю границу выбранных подтверждений, а не статистику отказов.

## Локальные данные и воспроизведение

Исходная выгрузка не изменялась. Производный индекс `data/.work/messages.jsonl` содержит текст сообщений и служит только локальному разбору. Его нельзя публиковать или добавлять в Git. Признак автора в индексе заменён техническим отпечатком; персональные сведения в самом тексте автоматически не удаляются, поэтому индекс остаётся приватным.

Из корня проекта:

```sh
python3 scripts/index_chat.py \
  'data/archive Centauri Carbon 🇷🇺' \
  --output data/.work/messages.jsonl
```

Скрипт использует только стандартную библиотеку Python 3.9+ и разрешает источник и выходной путь только внутри локальной `data/`. Повторный запуск перезаписывает указанный производный индекс. Служебные записи и текст превью внешних страниц не превращаются в текст сообщений; ссылки, даты, ID и связи ответов сохраняются.

В Markdown перенесены только пересказы и локальные указатели. Скрипт индексации и инструкции можно хранить в Git; `data/` исключена целиком.

## Границы технической проверки

Проверены 50 локальных ссылок, включая 21 указатель на существующие сообщения HTML-выгрузки. Для выбранных независимых эпизодов проверено различие признаков автора; продолжения WEB-02 и WEB-04 объединены по совпадению этого признака. На небольшом искусственном HTML проверены вложенный текст, переносы строк, связь ответа между страницами и наследование автора в последовательных сообщениях.

Правила `.gitignore` проверены настоящим `git check-ignore` в отдельном временном репозитории: исходная выгрузка, производный индекс, `.DS_Store` и Python-кеш исключаются. Сам рабочий каталог на момент проверки ещё не был инициализирован как Git-репозиторий; `git init`, коммиты и публикация здесь не выполнялись.

Статьи проверены по текстам, указанным фото и открытым первоисточникам. Печать, калибровки, смена прошивок, очистка пластины и сброс принтера самостоятельно не выполнялись. Причины, которые участники только предполагали, не повышены до подтверждённого диагноза.

Официальный FAQ для CC2 поддерживает общие проверки первого слоя; это не самостоятельное подтверждение исходов в чате. Историческое восстановление веб-интерфейса CC1 описано на основании опыта участников. Прямое открытие ряда старых страниц Wiki возвращало только оболочку сайта, поэтому их содержимое не использовано для технических утверждений.
