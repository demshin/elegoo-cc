# Публичный репозиторий и GitHub Pages

Договорённости от 2 ноября 2026 года. Выбран первый запуск на стандартном адресе GitHub Pages, без изменений существующего сайта demsh.in и DNS.

## Принятые решения

- Открыть исходники статей и сайта для участия сообщества через pull requests. Публикуемый набор включает статьи, код, скрипты, тесты, AGENTS.md, публичные основания ответов и документацию для участников.
- Сырой архив, промежуточные данные, локальные скиллы и журналы редактуры оставить вне публичного репозитория.
- GitHub Pages получает только готовый сайт из site/dist/, а не рабочий каталог проекта.
- Проверять PR автоматически. Владелец принимает изменения; после merge в main сайт обновляется автоматически.
- Новые темы и спорные изменения обсуждать с сообществом в GitHub Issues. В комментариях собирать случаи, подтверждения, возражения и ограничения; итог обсуждения фиксировать в связанном PR. Приглашения и сообщения участникам отправляет владелец, если отдельно не поручит это агенту.
- Обсуждение с сообществом помогает принять решение о статье, но не заменяет подтверждение успешного решения и повторяемости. Если оснований недостаточно, тема остаётся в Issues и не становится статьёй FAQ.
- Для кода использовать MIT, для статей и справочных текстов — CC BY-SA 4.0. Явно описать области действия лицензий и условия вкладов; не распространять их на чужую документацию и исходную переписку.
- Сохранить критерии FAQ: повторяющиеся проблемы, независимые случаи и подтверждённое успешное решение.
- Создание локального скилла проверки статей по архиву и документации отложить в [бэклог](backlog.md).
- Подключение собственного поддомена отложить. Для первого запуска доступ к Beget не нужен; настройки DNS и существующего сайта demsh.in не меняются.

## Адрес

Адрес сайта — https://demshin.github.io/elegoo-cc/, репозиторий — demshin/elegoo-cc. Astro получает SITE_URL=https://demshin.github.io и SITE_BASE=/elegoo-cc. В настройках Pages выбирается GitHub Actions; отдельный Custom domain не задаётся.

Основной сайт demsh.in опубликован из другого project repository — demshin/demsh.in. Его домен не наследуется новым проектом автоматически: такое наследование GitHub описывает для основного сайта аккаунта. Перенос главной в demshin.github.io владелец отклонил. Поэтому FAQ публикуется независимо на стандартном адресе проекта. [GitHub: домены нескольких репозиториев](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site/about-custom-domains-and-github-pages#using-a-custom-domain-across-multiple-repositories), [Astro: GitHub Pages](https://docs.astro.build/en/guides/deploy/github/).

Если позже понадобится elegoo-cc.demsh.in, его можно подключить отдельным изменением после проверки действующих DNS-записей. Доступ к API Beget должен оставаться локальным и не передаваться в GitHub Actions.

## Подготовка перед первым коммитом

- Сформировать явный набор публикуемых файлов и проверить обезличивание, включая исходники реестров, а не только сгенерированный сайт.
- Исключить локальные скиллы и служебные данные из Git. Отдельно проверить ассеты сайта.
- Подготовить правила участия, лицензии, шаблоны PR и Issues, инструкции по подтверждению решений и ограничения проверки.
- Разделить публичные проверки и локальные проверки, требующие сырого архива. Сейчас scripts/check_docs.py зависит от закрытой выгрузки.
- Подготовить CI для PR и отдельную публикацию после merge; проверить сборку без data/.
- Настроить адрес сайта и проверить ссылки, поиск, HTTPS, внешний вид на компьютере и телефоне.
- Перед первым коммитом показать владельцу ветку и точный staged diff.
